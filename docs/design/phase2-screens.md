# 企業級請假管理系統 — Phase 2 逐畫面設計

> 承接 Phase 1（`phase1-foundation.md`）已確認的架構方向：
> Navigation Rail + Bottom Nav／沿用五種角色／通知中心・全域搜尋・報表中心・假期規則試算列為必備／年度考核僅視覺統一。
> 本文件涵蓋：全域共用樣式（Shell／State／Toast／Dialog）與 17 個核心畫面的完整規格。

---

## Part A. 全域共用規範（所有畫面共用，避免重複）

### A.1 Layout Shell

**桌面（≥1024px）**
```
┌───────────────────────────────────────────────────────────────────┐
│ Top App Bar：[≡] 頁面標題          [搜尋 ⌕] [🔔3] [中/EN] [🌙] [頭像▾] │
├───────┬───────────────────────────────────────────────────────────┤
│ Nav   │                                                           │
│ Rail  │                     主要內容區 Content                     │
│ 72/240│                 max-width 1440px，左右 padding 32px         │
│ px    │                                                           │
│       │                                                           │
└───────┴───────────────────────────────────────────────────────────┘
```
- Nav Rail 預設收合 72px（僅圖示＋文字提示 tooltip），使用者可釘選展開為 240px（含文字標籤），狀態存於個人設定並記住。
- 具子項目的模組（請假／團隊／管理後台）在 Rail 中點擊後於下方展開次層，或於展開態直接顯示樹狀次層。

**平板（600–1023px）**：Rail 強制收合為 72px 圖示軌，不可展開；內容區 padding 縮為 24px。

**手機（<600px）**
```
┌─────────────────────────────┐
│ ← 頁面標題           [⋮ 更多] │  Compact App Bar，56px
├─────────────────────────────┤
│                             │
│         內容區（單欄）        │
│                             │
├─────────────────────────────┤
│ 🏠首頁 📝申請 📄假單 🔔通知 ⋯更多│  Bottom Nav，安全區 + 56–80px
└─────────────────────────────┘
```
- Bottom Nav 固定 4 項（依角色略有差異，見 Phase 1 §4.3）＋「更多」進管理/報表/年度考核/設定。
- 全域搜尋在手機收合為 App Bar 上的搜尋圖示，點擊後全螢幕搜尋 Overlay。

### A.2 State 樣式規範（所有列表/表單頁共用）

| 狀態 | 樣式規則 |
|---|---|
| **Loading（初次載入）** | 使用 Skeleton（灰階佔位方塊，含 shimmer 動畫），依實際版面比例呈現，不用轉圈圈；路由切換時於 App Bar 下方顯示 4px Linear Progress。 |
| **Loading（動作中，如送出表單）** | 主要按鈕內顯示 Spinner + 文字變為進行式（例如「送出中…」），按鈕與表單欄位鎖定防止重複送出。 |
| **Empty State** | 置中圖示（單色線性 illustration）＋一句 Headline＋一句輔助說明＋一個主要 CTA。不同頁面文案不同（見各畫面）。 |
| **Error State（頁面級）** | 網路/伺服器錯誤：整頁置中錯誤圖示＋「發生錯誤，請稍後再試」＋「重新載入」按鈕，保留 Nav 可離開。 |
| **Error State（表單級）** | 欄位下方紅字＋左側 4px 紅色 border＋icon，欄位 `aria-invalid="true"` 並以 `aria-describedby` 連結錯誤訊息；表單頂部若有多欄錯誤，加總覽 Banner「請修正以下 3 個欄位」。 |
| **Toast（Snackbar）** | 桌面：畫面左下角，寬度 344–512px；手機：貼齊 Bottom Nav 上方，滿版扣邊界 16px。單行文字＋最多 1 個文字動作連結。成功/資訊 4 秒自動消失；錯誤類不自動消失，需手動關閉。同時間最多疊 1 則，後進先顯示於堆疊底部依序消化。 |
| **Dialog** | 桌面：置中 Modal，寬度 400–560px（確認型）或 720px（表單型），背後 Scrim 40% 不透明；手機：確認型維持置中小型 Modal，複雜表單型改為全螢幕 Dialog（含頂部「取消／標題／儲存」）。破壞性操作（刪除、駁回、停用帳號）Dialog 主按鈕使用 Error 色並要求二次確認文字或輸入原因。 |

### A.3 無障礙共用規則

- 色彩對比：本文皆以文字/圖示 ≥4.5:1、大型文字與圖形元件 ≥3:1 為底線（實際色票見 Phase 3）。
- 焦點：所有互動元件需有可見 focus ring（2px，非僅色彩變化），Tab 順序依視覺順序，Modal 開啟時焦點鎖定（focus trap）並於關閉後歸還原觸發元件。
- 觸控目標：最小 44x44px（手機）／40x40px（桌面滑鼠）。
- 動態內容：Toast、即時待簽核數變化使用 `aria-live="polite"`；錯誤訊息使用 `aria-live="assertive"`。

### B1. 登入 Login

**畫面目的**：讓使用者以最少步驟安全登入，並提供企業 SSO 入口降低 IT 負擔。

**Layout**：置中卡片（桌面 400px 寬／手機滿版），左側可放品牌插畫（桌面 ≥1024px 顯示，平板以下隱藏）。

**Wireframe（桌面）**
```
┌─────────────────────────────────────────────┐
│  [品牌插畫/Illustration]   │   企業 Logo           │
│                          │   歡迎回來              │
│                          │   [ Email/工號        ] │
│                          │   [ 密碼          👁 ] │
│                          │   [ ] 記住我   忘記密碼？ │
│                          │   [   登入 Primary   ]  │
│                          │   ── 或 ──             │
│                          │   [ 使用企業 SSO 登入 ]  │
│                          │   語言：中文 ▾           │
└─────────────────────────────────────────────┘
```

**元件說明**：Text Field（Email/工號、密碼含顯示密碼切換）、Checkbox（記住我）、Text Button（忘記密碼）、Filled Button（登入）、Outlined Button（SSO）、語言 Select 固定於卡片底部（未登入前即可切換，確保錯誤訊息也在正確語系）。

**Interaction**：Enter 鍵可送出；密碼欄位遮罩預設開啟；SSO 按鈕導向 IdP 後回跳。

**Empty State**：不適用。

**Error State**：帳密錯誤 → 表單頂部 Banner「帳號或密碼不正確」（不指出是哪一個，避免帳號枚舉）；帳號被停用 → Banner 附「聯繫 HR」連結。

**Loading State**：按鈕內 Spinner，鎖定表單。

**Toast**：登出後導回本頁時，短暫顯示「您已登出」Toast。

**Dialog**：忘記密碼採跳轉頁而非 Dialog（需獨立可分享網址）。

**Responsive**：手機版移除左側插畫，Logo 置頂置中，其餘欄位滿版。

### B2. 儀表板 Dashboard（首頁）

**畫面目的**：登入後 5 秒內回答「我今天的假期狀態？」「我有什麼待辦？」「團隊今天誰不在？」。依角色顯示不同卡片密度（員工簡化／主管+簽核待辦／老闆+全公司總覽）。

**Layout**：桌面 12 欄 Grid；上方為「我的待辦」橫幅列，下方為卡片式 Widget 區（2–3 欄自適應）。

**Wireframe（桌面，主管視角）**
```
┌───────────────────────────────────────────────────────────┐
│ 歡迎回來，Anna｜今天是 2026/07/24（五）                        │
├───────────────────────────────────────────────────────────┤
│ [待簽核 5 筆 →]  [我的假單 2 筆審核中 →]  [今日團隊 3 人休假 →]  │
├───────────────────┬───────────────────┬─────────────────────┤
│ 我的特休餘額         │ 近期團隊行事曆(mini) │ 公告/政策更新         │
│  14 / 18 天 (環狀圖) │  週一到週五 head icon│  ・2026 國定假日公告  │
│  [立即申請]          │  [查看完整行事曆 →]  │  ・特休新制說明        │
├───────────────────┴───────────────────┴─────────────────────┤
│ 我最近的假單（列表，最多5筆，含狀態 chip）             [查看全部 →]│
└───────────────────────────────────────────────────────────┘
```

**元件說明**：Stat Card（環狀進度＋數字）、Mini Calendar Widget、Announcement List、Status Chip（簽核中/已核准/已駁回 用色彩區分＋不僅靠顏色，附文字與 icon）、Quick Action Button（立即申請）。

**Interaction**：卡片皆可點擊進入對應模組；「今日團隊休假」hover 顯示人員清單 tooltip。

**Empty State**：無待辦時，待辦橫幅整列改為「目前沒有待處理事項 🎉」單行提示，不佔滿版面高度。新人無歷史假單時，「我最近的假單」區塊顯示 Empty：「你還沒有請假紀錄」＋「申請第一筆假期」CTA。

**Error State**：單一 Widget 讀取失敗不影響其他 Widget，該卡片內顯示「載入失敗，重試」小連結，不用整頁錯誤。

**Loading State**：各 Widget 各自 Skeleton（避免整頁等待最慢的 API）。

**Toast**：從其他頁面動作後導回首頁時可能出現「假單已送出」等延續性 Toast。

**Dialog**：無（首頁不承載表單型操作）。

**Responsive**：手機改為單欄堆疊，待辦橫幅改為可橫向滑動的 Chip 列；Mini Calendar Widget 在手機縮為「今日/明日誰休假」單行清單。

### B3. 申請請假 Leave Application Form

**畫面目的**：讓員工在申請當下就掌握額度與衝突資訊，降低被退件機率。

**Layout**：桌面雙欄——左欄為表單，右欄為「即時試算面板」（Sticky，隨捲動固定）。

**Wireframe（桌面）**
```
┌───────────────────────────────┬─────────────────────┐
│ 申請請假                         │ 假期試算（Sticky）      │
│ 假別 [特休 ▾]                    │ 特休剩餘：14 天         │
│ 起始 [2026-08-03] 結束[2026-08-05]│ 本次申請：3 天（扣抵後11）│
│ [ ] 半天/時段    起 09:00 迄18:00 │ ⚠ 08/04 同部門2人已請假 │
│ 代理人 [王小明 ▾]                 │ [查看團隊行事曆]         │
│ 事由 [多行輸入框                 ]│                       │
│ 附件 [ 拖曳或選擇檔案 ]            │                       │
│                                 │                       │
│ [ 儲存草稿 ]      [   送出申請  ] │                       │
└───────────────────────────────┴─────────────────────┘
```

**元件說明**：Select（假別，選項含顏色 dot）、Date Range Picker、Switch（半天/時段切換後顯示 Time Picker）、Autocomplete（代理人，帶頭像與職稱）、Textarea（事由，需求最少字數提示）、File Upload（拖曳區＋檔案列表，可移除）、Sticky Summary Panel、Inline Warning（非阻斷式）。

**Interaction**：選擇假別即時打 API 取得餘額；日期選擇後 debounce 查詢衝突與計算扣抵天數（國定假日/例假日自動排除不計）；代理人若也在申請期間請假，顯示警示「王小明當週已排休」。

**Empty State**：無適用假別（如新人未達特休資格）→ 假別選單標示「尚無可用假別」並提供「了解特休規則」連結。

**Error State**：額度不足 → 送出按鈕不禁用但送出時跳出 Dialog 確認「超過可用額度 2 天，是否以事假遞補或仍要送出（需主管特別核准）」；欄位驗證錯誤依 A.2 表單級規則呈現。

**Loading State**：試算面板數字位置用 Skeleton bar；送出按鈕 Loading。

**Toast**：送出成功「假單已送出，目前等待王主管審核」＋「查看」動作連結；草稿已儲存 Toast。

**Dialog**：離開頁面若表單有未儲存變更 → confirm Dialog「是否儲存為草稿？」（儲存草稿／不儲存／取消）。

**Responsive**：手機改單欄，試算面板變為表單上方可收合的 Summary Card（預設展開餘額，其餘資訊點擊展開）。

### B4. 我的假單 My Leaves（含「過往假期」Tab）

**畫面目的**：集中管理進行中與歷史假單，支援快速篩選與再次查閱。

**Layout**：頁籤（Tab）切換「進行中/草稿」與「歷史紀錄」；上方為篩選列，下方為列表（桌面表格化、手機卡片化）。

**Wireframe（桌面）**
```
┌───────────────────────────────────────────────────────┐
│ [進行中/草稿] [歷史紀錄]           篩選：假別▾ 狀態▾ 年度▾ ⌕ │
├───────────────────────────────────────────────────────┤
│ 假別   狀態      日期            天數   目前關卡   操作      │
│ ●特休  簽核中    08/03–08/05     3     2/3 王主管   [檢視]  │
│ ●病假  已核准    07/10–07/10     1     -          [檢視]  │
│ ●事假  已駁回    06/01–06/01     1     -          [檢視]  │
├───────────────────────────────────────────────────────┤
│                    [載入更多 / 分頁 1 2 3 →]              │
└───────────────────────────────────────────────────────┘
```

**元件說明**：Tabs、Filter Chips/Select、Data Table（含排序）、Status Chip、分頁或無限捲動（建議 1000 人規模用「分頁」而非無限捲動，利於精準定位）。

**Interaction**：點列進入 B5 假單詳情；「簽核中」列可直接在列表 hover 顯示「撤回」快速操作圖示。

**Empty State**：「進行中/草稿」無資料 →「目前沒有進行中的假單」＋「申請請假」CTA；篩選後無結果 →「找不到符合條件的假單」＋「清除篩選」。

**Error State**：列表讀取失敗，表格區以整塊 Error State（A.2 頁面級簡化版，維持頁籤與篩選可操作）呈現＋「重試」。

**Loading State**：表格 Skeleton Rows（顯示 5 列灰色佔位）。

**Toast**：撤回成功「假單已撤回」。

**Dialog**：撤回/取消假單需 confirm Dialog，說明額度是否歸還；銷假需求另開 B5 內的表單型 Dialog。

**Responsive**：手機表格轉為卡片列表，每卡顯示假別色條＋日期＋狀態 Chip，點擊進詳情；篩選收進「篩選」Bottom Sheet。

### B5. 假單詳情 Leave Detail（簽核歷程時間軸）

**畫面目的**：讓申請人與簽核人看到完整脈絡與歷程，減少「已讀不回」與重複詢問。

**Layout**：桌面雙欄——左為申請內容，右為垂直時間軸（Timeline）。

**Wireframe**
```
┌───────────────────────────┬───────────────────────┐
│ ← 返回                       │ 簽核歷程                │
│ 特休｜2026/08/03–08/05（3天）   │ ● 已送出 07/24 10:02     │
│ 狀態：簽核中（2/3）             │ ● 王主管 已核准 07/24 14:30│
│ 代理人：王小明                  │ ○ 李協理 待處理           │
│ 事由：家庭旅遊                  │                        │
│ 附件：（無）                    │                        │
│ [撤回申請] [申請銷假]（依狀態顯示）│                        │
└───────────────────────────┴───────────────────────┘
```

**元件說明**：Vertical Stepper/Timeline（已完成=實心圓+色彩，待處理=空心圓灰階）、Status Badge、Action Buttons（依狀態與角色顯示：申請人看到撤回/銷假；簽核人看到核准/駁回/加簽，見 B8）。

**Interaction**：時間軸每點可展開查看簽核意見備註；若使用代理簽核，該節點標註「王主管（由 陳副理 代理）」。

**Empty State**：不適用（此頁必有資料）。

**Error State**：找不到假單或無權限 → 404/403 頁面樣式：「找不到此假單，或您沒有檢視權限」＋「返回我的假單」。

**Loading State**：Skeleton 雙欄骨架。

**Toast**：撤回/銷假成功後 Toast，並返回列表頁。

**Dialog**：銷假 Dialog 需填「銷假原因」＋日期範圍（可部分銷假），送出後狀態變為「銷假審核中」。

**Responsive**：手機改為單欄，時間軸移至內容下方，可摺疊「詳細時間戳」。

### B6. 團隊行事曆 Team Calendar

**畫面目的**：主管/員工快速掌握團隊人力覆蓋率，輔助排休決策與衝突判斷。

**Layout**：頂部工具列（月/週/清單 檢視切換、部門/成員篩選、今天按鈕）＋月曆主體。

**Wireframe（桌面，月檢視）**
```
┌───────────────────────────────────────────────────────┐
│ [◀ 2026年8月 ▶]  [今天] 檢視：[月|週|清單]  部門：[研發部▾] │
├───────────────────────────────────────────────────────┤
│  一   二   三   四   五   六   日                         │
│  ...  ...  ...  ...  [3]  4    5                         │
│              王小明●特休                                   │
│              陳大文●病假                                   │
│  人力覆蓋率提示：08/03 研發部出勤率 70%（低於80%門檻，標黃）      │
└───────────────────────────────────────────────────────┘
```

**元件說明**：Segmented Button（檢視切換）、Department Multi-select、Calendar Grid（同 MD3 Date/Calendar 元件延伸）、Event Chip（依假別色彩，超過3筆該日顯示「+2 more」）、Coverage Indicator（人力覆蓋率低於門檻時儲存格底色標示，非純色彩需搭配圖示與文字，符合 WCAG）。

**Interaction**：點事件 Chip 開 Popover 顯示簡要（姓名/假別/時段），點「+more」展開當日清單；點空白日期若有權限可快速建立請假（跳轉 B3 並帶入日期）。

**Empty State**：篩選部門無任何假期紀錄 →月曆維持顯示但底部提示「此篩選條件下本月無請假紀錄」。

**Error State**：月曆資料載入失敗 → 月曆格維持骨架＋「重新載入」按鈕於工具列下方。

**Loading State**：月曆格 Skeleton（灰色格線先出，事件延遲淡入）。

**Toast**：無（此頁多為唯讀瀏覽）。

**Dialog**：點事件 Chip 在手機上以 Bottom Sheet 呈現（取代 Popover）。

**Responsive**：手機預設「清單檢視」（依日期排序的請假清單）取代月曆格，可切換「週檢視」橫向捲動；月檢視在手機為選用而非預設，避免格子過小難點擊。

### B7. 簽核中心 — 待簽核列表 Approval Queue

**畫面目的**：讓簽核人快速排序、篩選並批次處理低風險假單，降低簽核延遲。

**Layout**：頂部統計＋篩選列，列表支援多選＋批次操作 Toolbar（選取後浮現）。

**Wireframe（桌面）**

**Responsive**：此為進階管理功能，手機僅提供「檢視」（唯讀），編輯導引至「請於桌面版編輯」提示卡。

### B16. 個人設定 Settings（個人資料／外觀／通知偏好）

**畫面目的**：讓使用者自助管理語言、深色模式、通知頻率，減少對 IT/HR 的詢問。

**Layout**：左側設定分類 Tabs（桌面）或清單（手機），右側對應表單。

**Wireframe（桌面，外觀分頁）**
```
┌────────────┬──────────────────────────────────────────┐
│ 個人資料     │ 外觀設定                                    │
│ ▶外觀        │ 主題：[ 淺色 | 深色 | 跟隨系統 ]（Segmented）    │
│ 通知偏好      │ 語言：[ 繁體中文 ▾ ]                          │
│              │ 導覽列：[ ] 預設展開導覽軌（顯示文字標籤）        │
└────────────┴──────────────────────────────────────────┘
```

**元件說明**：Tabs/List、Segmented Button（主題三選一）、Select（語言）、Switch（導覽展開偏好）、通知偏好分頁另含「即時/每日彙整/僅站內」三選一 + 各事件類型開關（Toggle List）+ **Slack 連結卡片**（見下）。

**Wireframe（桌面，通知偏好分頁，新增 Slack 區塊）**
```
┌────────────┬──────────────────────────────────────────┐
│ 個人資料     │ 通知偏好                                    │
│ 外觀         │ 頻率：[ 即時 | 每日彙整 | 僅站內 ]（Segmented）  │
│ ▶通知偏好     │ 事件開關：[✓]簽核結果 [✓]待簽核 [ ]政策更新     │
│              ├──────────────────────────────────────────┤
│              │ Slack 通知                                 │
│              │ 🟢 已連結：@wang.xiaoming        [取消連結]  │
│              │ [✓] 同步發送簽核/假單通知到我的 Slack 私訊     │
└────────────┴──────────────────────────────────────────┘
```

**Interaction**：主題與語言變更即時套用預覽（不需按儲存），其餘表單需「儲存」；深色模式切換有平滑過場（尊重 `prefers-reduced-motion`，該情況下無過場動畫）。Slack 區塊：未連結時顯示「前往連結 Slack 帳號」按鈕，點擊走 Slack OAuth 導回；已連結則顯示 Slack 使用者名稱與「同步通知」開關，關閉後僅保留站內/Email 通知、不影響公司層級的每日團隊摘要（那是頻道推播，非個人開關可控制）。

**Empty State**：不適用。

**Error State**：儲存失敗 → Toast 錯誤並保留使用者輸入值；Slack OAuth 失敗（使用者取消授權或權限不足）→ 區塊內顯示「連結失敗，請重試」，不中斷其他設定的儲存。

**Loading State**：首次進入 Skeleton 表單；Slack 連結狀態查詢中顯示小型 Skeleton。

**Toast**：「設定已儲存」／「Slack 帳號已連結」／「已取消 Slack 連結」。

**Dialog**：取消 Slack 連結需 confirm（說明取消後將不再收到 Slack 通知，但站內通知不受影響）。

**Responsive**：手機分類改為清單式導向各自子頁面（非並列 Tabs），符合單欄操作習慣。

### B17. 管理後台 — Slack 整合設定 Slack Integration

**畫面目的**：讓 HR/管理員以公司層級連接 Slack Workspace，設定哪些事件要發送、發送到頻道或私訊，並管理每日團隊摘要的頻道對應，取代「所有通知只能在網頁看」的現況。

**Layout**：上方為連接狀態卡片，下方為事件—發送對象對照表格。

**Wireframe（桌面）**
```
┌───────────────────────────────────────────────────────┐
│ Slack 整合設定                                             │
├───────────────────────────────────────────────────────┤
│ 🟢 已連接工作區：Acme Inc.（#hr-leave-notice）  [重新授權][中斷連接]│
├───────────────────────────────────────────────────────┤
│ 事件                     發送方式              頻道/對象         │
│ 待簽核通知（可互動卡片）    [私訊簽核人 ▾]        —              │
│ 簽核結果通知              [私訊申請人 ▾]        —              │
│ 每日團隊請假摘要 — 研發部  [發送到頻道 ▾]        #dev-team       │
│ 每日團隊請假摘要 — 行銷部  [發送到頻道 ▾]        #marketing      │
│ 每日團隊請假摘要 — 其餘部門 [不發送 ▾]           —              │
│ 摘要發送時間：[ 08:00 ▾ ]                                     │
└───────────────────────────────────────────────────────┘
```

**元件說明**：Connection Status Card（未連接/已連接/授權過期三態，各自不同底色與圖示）、「Add to Slack」OAuth 按鈕、Event-Channel Mapping Table（每列為一種事件，Select 選發送方式，第二個 Select 為 Slack 頻道選單，選單內容為即時透過 Slack API 取得的頻道清單，含搜尋）、Time Picker（摘要發送時間）。

**Interaction**：點擊「連接 Slack」開新視窗導向 Slack OAuth 授權頁，導回後即時顯示 Workspace 名稱並帶出頻道清單供選擇；切換某事件的發送方式為「發送到頻道」時，第二欄 Select 才會啟用（否則呈現 disabled 樣式的「—」）；每列變更即時儲存（不需整頁「儲存」按鈕，逐項變更逐項生效，並各自跳出小型確認 Toast）。

**Empty State**：尚未連接 Slack → 整頁改為單一置中卡片：「尚未連接 Slack」＋說明可獲得的功能（簽核卡片、每日摘要）＋「連接 Slack」主要按鈕，不顯示下方表格。

**Error State**：Token 過期/授權被 Slack 端撤銷 → 連接狀態卡片變為警示樣式（🟡），文案「Slack 連線已中斷，通知已暫停發送，請重新授權」，且此警示同時出現在管理員登入後的儀表板（B2）待辦區，避免管理員沒發現通知早已停止；頻道清單載入失敗 → Select 顯示「無法取得頻道清單，請重試」。

**Loading State**：頻道清單載入中，Select 內顯示 Skeleton 選項列；OAuth 導回後等待 Workspace 資訊時，狀態卡片顯示 Skeleton。

**Toast**：「Slack 已連接」／「已更新『每日團隊請假摘要 — 研發部』的發送設定」／「已中斷 Slack 連接」。

**Dialog**：「中斷連接」需 confirm，並明確說明中斷後所有簽核卡片與每日摘要都會停止發送，直到重新連接；「重新授權」不需 confirm（屬修復性操作）。

**Responsive**：手機僅提供「檢視」連接狀態與目前事件對照表（唯讀），編輯導引至「請於桌面版設定」提示卡，理由同 B15（多欄位設定不適合窄版操作）。

```
Slack 每日團隊摘要樣式（發送到 #dev-team，08:00）
┌──────────────────────────────┐
│ ☀️ 今日團隊請假提醒（研發部）      │
│ • 王小明－特休（全天）             │
│ • 陳大文－病假（全天）             │
│ 共 2 人請假，今日出勤率 85%        │

```
