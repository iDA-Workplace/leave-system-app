# 維運腳本

跟 `../migrations/` 不一樣：那邊是「系統結構的變更」，每一份都要跑過一次；
這邊是「偶爾才需要手動跑一次」的維護動作，平常不用管。

執行方式都一樣：到 Supabase 主控台 → SQL Editor → 貼上整份 → Run。

| 檔案 | 用途 |
| --- | --- |
| `test_data_list.sql` | 唯讀。上線前清測試資料用：把請假單、考核進度、按摩期數、假單附件檔案**逐筆**列成一張表，看完再決定刪哪些。 |
| `clear_all_test_data.sql` | ⚠️ **只能在正式上線前使用** —— 不分辨測試或真實資料，上線後執行會刪光所有真實的請假、考核、按摩紀錄。上線後清測試資料：先跑 `test_data_list.sql` 挑出要刪的，再另外寫只刪那幾筆的語法。**2026-11 上線前清測試資料（使用者確認全是測試資料後）。** 刪全部請假單＋簽核、考核作答與評分（考核週期與名單保留、進度歸零）、全部按摩期數（含已抽籤的）。保留個人假期額度的手動指定。Slack 上 60 天內的按摩報名公告會被排程改成「本期已取消」。附件檔案要另外到 Storage 刪（見下方）。 |
| `holiday_impact_preview.sql` | 唯讀。國定假日正式啟用（`20261114_holidays_go_live.sql`）之前跑：列出中間有國定假日的跨日假單（天數會變少）、以及剛好請在國定假日的單日假單（建議 HR 確認）。 |
| `reset_test_data_preview.sql` | **先跑這個。** 唯讀，只列出「會刪什麼、會留什麼」的筆數，不會改到任何資料。 |
| `reset_test_data.sql` | 正式上線前把測試期間 key 的資料清乾淨：刪請假單與考核作答、清掉個人假期額度的手動調整（回到比照勞基法），考核參與者「人留著、狀態歸零」。**不會**動到員工帳號、登入密碼、附件檔案，以及考核週期、假別、全公司預設額度、簽核流程等設定。 |
| `clear_leave_requests.sql` | **只**刪請假單與它的簽核紀錄，其他一律不動。跟上面那支最關鍵的差別是：它**不會**清掉「個別指定的假期天數」。如果你替某些同仁設過個別天數，只想清假單就用這一支。 |
| `rename_leave_type.sql` | 改假別的**中文名稱**。網站上沒有這個入口（「假期類型」只能改額度、「假別英文名稱」只能改英文名），所以只能從這裡改。改名是安全的 —— 程式辨識假別看的是 `is_annual` / `is_wfh` 旗標，不是名字。 |
| `remove_dead_delegate_cron.sql` | **一次性的清理。** 刪掉 `auto-deactivate-delegates` 這個排程 —— 它操作的資料表在 2026-08 隨「代理審核」功能一起刪掉了，所以每天執行、每天失敗。只刪排程不刪資料，而且會先確認那張表真的不在才動手。 |
| `ban_inactive_users.sql` | **一次性。** 把以前就「刪除（停用）」、但登入帳號沒被封鎖的同仁封鎖登入（2026-11 修正 manage-users 之前停用的人才需要）。不刪任何資料，之後按「恢復帳號」會自動解除。分兩步：先預覽名單，再執行封鎖。 |

每一份都可以重複執行，跑第二次不會出錯。

## 刪除假單附件檔案（Storage）

Supabase 不允許用 SQL 刪 Storage 裡的檔案，要在主控台操作：

1. Supabase 主控台左側 **Storage** → 點 **leave-attachments**
2. 裡面一個資料夾是一位同仁（資料夾名稱是同仁的 id）
3. 勾選全部資料夾 → 按 **Delete** → 確認

刪檔案不會影響假單資料；但假單還在的話，那張假單的附件連結就會打不開，所以要先確認對應的假單也已經刪掉。

## `move_preview_to_1pm.sql`

「隔天請假名單」的 Slack 預告從下午 4:00 改成下午 1:00（2026-11）。只改 pg_cron 排程的小時欄位，程式不用重新部署。可以重複執行。

## `launch_readiness_check.sql`

上線前檢查（只讀取）：測試資料清了沒、按摩測試模式、按摩負責人、待開通的新人、每位在職同仁缺不缺
Slack ID／審核流程／直屬主管／入職日期／部門、看起來像測試帳號的帳號、核准通知對象、2027 國定假日、
App 通知裝置數。可以隨時重複執行。

## `pause_leave_digest_until_2027.sql`

上線後、2027/1/1 開放請假前，暫停「今日請假名單」與「隔天請假名單」兩個排程（系統裡沒有假單，只會一直發
「沒有人請假」）。同時建立一次性排程 `resume-leave-digest-2027`：2027/1/1 台北 08:00 自動恢復兩個排程，
然後刪掉自己。按摩公告、逾期假單處理不受影響。最下面有「手動提早恢復」的語法。
