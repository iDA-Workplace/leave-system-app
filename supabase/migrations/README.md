# Manual migrations

This app's Supabase project isn't wired into this repo (no CLI project link,
no service-role key here) -- so these `.sql` files are **not** applied
automatically by anything. Run them by hand:

1. Go to your Supabase project dashboard → **SQL Editor** → **New query**.
2. Paste the contents of the migration file in filename order.
3. Run it. Every statement here is idempotent, so re-running a file that's
   already been applied is harmless.

| `20261110_security_lockdown.sql` | **Security fix (2026-11), run in production.** Found by exporting the live policies: anyone signed in could make themselves admin/HR/boss (`users_update_self` had no column limit), approve their own leave (`requests_update_own`, `requests_insert`), or forge `leave_approvals` rows; anyone *not* signed in could read the whole `users` table and `annual_leave_summary`; `handle_new_user` took the role from sign-up metadata. Website code unchanged. Tested in `../tests/security/` (49 checks). | Closing the holes above. Nothing in the app depends on it, so it can run any time. |
